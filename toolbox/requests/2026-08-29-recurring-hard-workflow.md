# 3시간 간격 하드 워크플로 자동 실행

## 확정 요구사항

- Windows 로그인 시 Codex 데스크톱 앱을 자동으로 실행한다.
- Blogger Toolbox 하드 워크플로를 3시간 간격으로 자동 실행한다.
- 실행 직전에 ChatGPT 계정의 5시간 사용량 창을 확인한다.
- 5시간 창의 잔여 비율이 20% 미만이면 해당 회차를 시작하지 않는다.
- 잔여 비율을 인증된 값으로 읽지 못하면 값을 추정하지 않고 경고를 기록한 뒤 하드 워크플로를 실행한다.
- 이전 하드 실행이 완료되지 않았으면 새 회차를 만들지 않고 최초 미완료 단계부터 재개한다.
- 시스템 종료 및 예약 종료는 설정하지 않는다.

## 구현 방향

- `scripts/check-codex-five-hour-usage.ps1`가 Codex app-server의 `account/rateLimits/read` 결과에서 300분 창을 찾아 잔여 비율을 계산한다.
- 검사 결과는 `eligible`, `below_threshold`, `unavailable` 중 하나로 출력한다.
- 자동화는 `below_threshold`이면서 확인된 잔여 비율이 20% 미만일 때만 변경·게시·Git 작업 없이 건너뛴다.
- `eligible`이면 정상 실행하고, `unavailable`이면 조회 실패 경고만 기록한 뒤 정상 실행한다.
- `below_threshold`와 `unavailable`은 종료 코드 0을 반환해 예약 실행 실패나 자동 재시도를 유발하지 않는다.
- 한 예약 회차에서는 사용량 검사를 한 번만 수행하며, 조회 실패 시 같은 회차에서 재시도하지 않는다.
- 검사 스크립트는 예약 환경의 Windows PowerShell 5.1과 현재 PowerShell 양쪽에서 같은 JSON과 종료 코드를 반환한다.
- 자동화 메모리에 남은 과거 실행 기록은 진단 이력일 뿐이며, 현재 프롬프트의 실행 조건보다 우선하지 않는다.
- 각 실제 하드 실행은 기존 자동 작업 절차에 따라 독립 실행 ID, 결과 JSON, 커밋, 푸시와 공개 배포 증거를 갖춘다.

## 안전 경계

- OAuth 토큰과 계정 자격 증명은 저장소에 기록하지 않는다.
- 사용량 조회 실패를 20% 이상이라고 표시하지 않지만, 조회 불능만으로 예약 작업을 막지는 않는다.
- 삭제, Blogger 휴지통 이동, 공개 글의 초안 전환은 자동화 범위에 포함하지 않는다.
